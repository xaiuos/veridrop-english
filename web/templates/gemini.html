FAQ (selected)

Why do Gemini API relays so often return model_not_found?

Three possibilities: ① the relay only proxies some Gemini models (many only carry the 3.x preview series, not 2.5); ② model-name spelling differences (gemini-2.5-flash vs models/gemini-2.5-flash); ③ the model has been delisted. Veridrop runs a preflight before submission, identifying dead models within 500ms and offering the available list instead.

What should max_completion_tokens be set to when testing Gemini 3.x preview?

At least 64; 128+ recommended. Gemini 3 enables thinking by default and burns 30-60 reasoning_tokens before emitting text. If max is too small (< 32), thinking fills the budget leaving no room for text — you get an empty string with finish_reason=length.

Why isn't the native Gemini /v1beta/models/X:generateContent path supported?

99% of third-party Gemini relays expose only the OpenAI-compatible protocol, and Google itself offers an OpenAI-compatible endpoint at /v1beta/openai. Maintaining two independent detection paths is costly and easily introduces translation layers that distort results, so we go deep on the OpenAI-compatible path.

Can Veridrop test the official Google Gemini API too?

Yes. Set base_url to https://generativelanguage.googleapis.com/v1beta/openai and use an AIza... key from Google AI Studio as the api_key. The official Google endpoint should score 100 on all 7 checks and serves as a baseline for comparing third-party relays.
