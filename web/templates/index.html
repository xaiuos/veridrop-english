FAQ (selected)

What is the thinking signature, and why is it the gold standard for authenticity verification?

When Claude thinks through a problem, the Anthropic server stamps a cryptographic "fingerprint" (like an official Anthropic seal on a parcel). Only Anthropic's own key can produce this seal — a relay cannot forge it no matter how hard it tries. Veridrop checks for exactly this seal. If the relay's responses to you lack the seal or carry a wrong one, it is not real Claude — it may have swapped in some cheaper model.

The thinking signature is a server-side cryptographic artifact returned in the signature field of the response when Claude enables extended thinking, 500-2000 characters long. It is generated by the Anthropic server and carries cryptographic verification — relays theoretically cannot forge it. Veridrop uses it as a core 25%-weight check; any relay that cannot return the signature (or returns an abnormal length) can be judged as not genuine Claude.

How do I choose a Claude relay? Which signals show it is trustworthy?

Three simple steps: ① Run Veridrop once — a total score of 85+ is generally usable, and 100 usually means a 1:1 pass-through to the official API; ② Check the page for red "critical" flags — if present, the relay may be swapping models, so switch providers; ③ Look up the relay's history on the leaderboard to see how it tested for others — ones that keep scoring high across 10+ tests are more trustworthy. Cheap relays usually cut corners; trust the score over the price.

Four things matter: ① Run Veridrop full mode and check whether thinking signature scores 100; ② Check the usage field for foreign-origin traces beyond claude_* (e.g. usage_source: anthropic appearing in an OpenAI response means it is wrapped by a relay); ③ Check whether the stream / non-stream input_tokens / output_tokens difference on the same prompt is ≤ 5%; ④ Check whether message IDs follow the msg_ / toolu_ / srvtoolu_ prefix convention — UUID-like IDs are a common relay forgery.

How do I expose Kiro / Amazon Q fakes pretending to be Claude?

Some relays actually run Amazon's own "wrapped Claude" on the backend (product names Kiro or Amazon Q). Amazon's version strips out Claude's thinking "fingerprint" — because it goes through a simplified interface. Veridrop tests for this: no Anthropic fingerprint seal = immediately judged not real Claude. In short, Veridrop uses a secret relay-unforgeable secret as a demon-revealing mirror — fakes fall apart in 5 seconds.

Kiro and Amazon Q are Amazon's Claude stand-in gateways running AWS Bedrock's simplified interface, and their responses do not return the thinking signature (signature generation requires Anthropic's private key, which Bedrock does not implement). Veridrop scores the thinking_signature detector at 0, the 25% weight zeroes out, and the overall verdict is locked to marginal or failed. The same applies to other Bedrock-routing relays.

Does Veridrop log my API key?

No. The API key you enter is used by our program only for the few dozen seconds of the detection and is immediately wiped from memory once it finishes — never written to any file, log, or database. Your key will never be found on Veridrop's servers. The report page only shows a masked version (like sk-y7xU••••••0h). Our code is fully public on GitHub — if you are concerned, audit it yourself or download it and run it on your own machine.
