{% if protocol == 'openai' %} What does each OpenAI check test?
Basic Request
Sends a minimal Chat Completions request to confirm the API is reachable and assistant text can be extracted.
Model Consistency
Verifies response.model matches the requested model and checks output-token stability across multiple low-temperature calls.
Function Calling
Forces tool_choice, validating call_ IDs, type=function, function names, and arguments JSON.
Structured Output
Uses response_format=json_schema and checks whether returned content parses against the schema.
Protocol Conformance
Passively checks official fields like chatcmpl- IDs, chat.completion, choices, finish_reason, and usage.
Streaming Consistency (Integrity)
Compares whether stream and non-stream responses to the same prompt agree on text, finish_reason, and usage.
Token Billing
Checks whether the relay's input/output token counts are self-consistent, compared against the stream/non-stream results in the same run and locally expected deltas.
Long Context Authenticity
Must be enabled at submission — uses needle-in-haystack probes at 32k → 100k → 200k token tiers to verify the relay truly delivers its advertised context window (catching truncation / routing to small-window models). The extreme tier adaptively probes up to 950k+ at the model's full limit.
{% elif protocol == 'gemini' %} What does each Gemini check test?
Basic Request
Sends a minimal generateContent request to confirm the API is reachable and Gemini text responses can be extracted.
Model Response Shape
Checks that modelVersion, responseId, finishReason, candidate, and safety fields are complete.
Function Calling
Forces Gemini to return functionCall, checking that the function name and args are structured objects.
Structured Output
Uses responseMimeType=application/json and responseSchema, checking whether returned content parses against the schema.
Protocol Conformance
Passively checks native Gemini fields like candidates, content.parts, safetyRatings, and usageMetadata.
Streaming Consistency
Compares whether generateContent and streamGenerateContent on the same prompt agree on text, finish reason, and usage fields.
Token Usage
Checks that usageMetadata exists, that token statistics are self-consistent, and that token deltas between short and long texts are reasonable.
{% else %} What do the 12 checks each test?
Identity Consistency
Asks the model to self-identify; the response must contain "Claude" and "Anthropic" and must not claim to be another brand (Kiro, AWS Q, etc.).
Behavioral Signature
3 behavioral fingerprint questions (markdown style, list preference, refusal tone) — genuine Claude has distinctive answer patterns.
Thinking Signature ⭐
The core check: the encrypted signature bytes returned in Claude thinking blocks, which no relay can forge.
Model Consistency
Verifies response.model matches the request and that output length is stable across calls (coefficient of variation).
Knowledge Accuracy
5 common-knowledge questions about Anthropic (CEO, HQ, Constitutional AI, etc.) — many wrong answers suggest the backend is not real Claude.
PDF Document Recognition
Submits a base64 PDF + magic string and checks whether the model extracts it correctly — relays that strip multimodal support will fail.
Structured Output (Tool Use)
Real tool_use calls validating 5 sub-items: toolu_ ID prefix, JSON schema match, stop_reason, and more.
Protocol Conformance
SSE event sequences and content block types must conform to Anthropic's official spec (passive; no extra requests sent).
Response Integrity
Streamed and non-streamed calls on the same prompt must return consistent text, input_tokens, and stop_reason.
Token Usage
Checks that Claude Messages' usage.input_tokens/output_tokens exist, that long/short prompt deltas are reasonable, that short outputs are not over-reported, and cross-validates against stream and count_tokens.
Message ID Conformance
Message id must start with msg_ and tool blocks with toolu_. UUIDs or hardcoded tool_1 are typical forgery tells.
Long Context Authenticity
Must be enabled at submission — uses needle-in-haystack probes at 32k → 100k → 200k token tiers to verify the relay truly delivers its advertised context window (catching truncation / routing to small-window models). The Anthropic path uses the official count_tokens endpoint for precise token budgeting; the extreme tier adaptively probes up to 950k+ at the model's full limit (Sonnet 4.6 / Opus 4.6/4.7 are all 1M).
