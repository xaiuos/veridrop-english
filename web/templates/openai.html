OpenAI / GPT Relay Detection

Veridrop runs 8 Chat Completions protocol checks plus usage-field backend fingerprinting to tell in 1 minute whether a relay genuinely passes through GPT, or secretly routes requests to a Claude / Gemini backend disguised as OpenAI responses. Free, no API key retention, open source.

Behavioral/protocol-level verification: This detection cannot reliably distinguish a genuine high-end model from a low-end model impersonating one. What we test is whether the relay interface conforms to the OpenAI Chat Completions protocol spec, whether capabilities are complete, and whether the usage field matches the official response shape.

FAQ (selected)

I paid for GPT — how do I know the relay didn't secretly swap in a cheaper model?

Look for fields that give the game away. Official OpenAI responses contain exactly three token-count fields; but if the relay secretly routes your request to a Claude backend and repackages it as OpenAI format, Anthropic-side fields often leak through. The moment Veridrop catches such fields that should never appear, it flags them as "critical issues" and drops the overall rating to amber.

In short: genuine GPT answers by OpenAI's own manual; lazy fake wrapper layers often leave traces of the other vendor.

I scored 75 — why is the ring still amber instead of green?

The score is only one dimension. Veridrop also checks for critical issues — even if the score clears the pass line, a single critical issue (like the leaked fields above) downgrades the overall verdict to amber "use with caution".

This usually means the interface works and returns results, but possibly not with the model you think you are using. Casual chat and everyday writing may be fine; but for running code or serious tasks, consider switching providers.

The result says "0 GPT models available" — is the relay down?

Most likely not; the key probably doesn't have GPT model access enabled. Many multi-vendor relays sell models grouped by vendor — some customers buy Claude plans, others Gemini plans, and without a purchase the corresponding models are unavailable.

Before detecting, Veridrop quickly checks which models your key can use — if you are on the OpenAI page with 0 GPT models, it will automatically suggest "this key can actually use X Claude models — test there instead?" One click and you are there.

Why can't OpenAI detection "guarantee authenticity" the way Claude's can?

Because OpenAI doesn't put a "mathematical proof" grade anti-counterfeit code in its responses. Claude has an encrypted signature called the thinking signature that relays cannot forge, so Veridrop can give very definitive conclusions on the Claude side.

On the OpenAI side we can only judge from indirect clues — does the behavior look like GPT, are field formats correct, are capabilities complete — hence our positioning as "behavioral/protocol-level" detection. It can tell you "looks normal" or "looks suspicious", but not 100% mathematical proof. For a definitive conclusion, test the same relay with a Claude model.
